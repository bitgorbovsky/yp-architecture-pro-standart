### <a name="_qmphm5d6rvi3"></a>**Решение**
#### Новые сущности и компоненты
**Предварительная заявка** - предварительная заявка на депозит, цель которой - обозначить намерение клиента зарегистрироваться в банке и разместить депозит под выбранные условия. Генерируется незарегистрированными клиентами. При обработке П.З. клиент должен пройти процедуру идентификации в отделении банка. В течение жизненного цикла П.З. проходит через следующие системы:
* Сайт - П.З. создаётся через сайт.
* Система call-центра - П.З. реплицируется в систему call-центра и передаётся операторам на обработку, дополнение деталей.
* АБС - после обработки в системе call-центра П.З. перемещается в АБС. На основе П.З. в АБС создаются уже прямые заявки на депозит для зарегистрированных клиентов.
Прямая заявка на депозит отличается от П.Я. на депозит тем, что приводит непосредственно к открытию депозита.

Для работы с П.З. необходимо реализовать в АБС раздела для работы с П.З. В рамках обработки П.З. в данном разделе АБС необходимо обеспечить возможность создания прямой заявки на кредит для уже зарегистрированного клиента.

**Предложение по депозиту** - сущность, схожая по основной своей структуре с заявкой на депозит, но которая при подтверждении не приводит к созданию депозита для клиента, а просто необходимая для отображения персональных предложений клиенту. Может быть реализовано, как атрибут основной заявки, который сообщает о системе о том, что при подтверждении не создавать депозит, а просто сохранить, как предложение.

**CDC** - набор компонентов, нацеленный на частичную синхронизацию данных между базами данных. В рамках MVP CDC применяется для двухсторонней синхронизации данных по заявкам между СУБД Интернет-Банка (MSSQL) и CУБД АБС (Oracle). Эта технология позволяет синхронизировать данные с минимальной нагрузкой на основные базы данных, и такая синхронизация приближена к режиму реального времени.
Основная идея применения CDC заключается в буферизации потока заявок при их приёме в АБС.

**Загрузчик АБС (ABSLoader)** - компонент связанный с CD и отвечающий за загрузку данных в АБС. Основная идея: буферизация потока прямых (с интернет банка) и предварительных заявок (с сайта) по депозитам перед Автоматизированной Банковской Системой. Это позволит обеспечить приемлемое масштабирование работы системы в условиях высокой нагрузки на АБС (Oracle).

**Загрузчик ИБ (IBLoader)** - компонент, связанный c CDC и отвечающий за загрузку данных по результатам обработки заявок из АБС в СУБД Интернет-Банка. Это позволит пользователю Интернет-Банка видеть обновления статуса заявок в режиме, близком к реальному времени.

**Синхронизация продуктов** - компонент, запускающий раз в сутки перенос данных из АБС в базу данных сайта данных по депозитным продуктам и их ставкам. Данных по депозитным продуктам немного, ставки по ним обновляются раз в сутки, поэтому здесь достаточно простого сервиса, запускаемого по расписанию.

**Генерация персональных предложений** - компонент, запускающий раз в некоторое время анализ данных по счетам клиентов и генерирующий заявки на депозит специального вида, которые являются предложениями по депозиту. Такие заявки также обрабатываются сотрудниками отдела депозитов и сотрудниками отдела кредитв, но их подтверждение не приводит к созданию депозита, а приводит к отображению персонализированных предложений в Интернет-Банке.
#### Задачи для достижения цели
1. **Сайт**
	1. Подключение сайта к базе данных для хранения данных по заявкам и продуктам банка.
	2. Интеграция сайта с модулем создания предварительных заявок.
	3. Реализация периодического процесса для загрузки в БД сайта данных по депозитным продуктам и их ставкам.
2. **Интеграция сайта и call-центра**
	1. Реализация интеграционного процесса на стороне системы call-центра для переноса заявок с сайта в систему call-центра. Синхронизация заявок происходит через API сайта.
	2. Реализация переноса обработанных заявок из систем сall-центров в Kafka (топик DepositPreRequests) для дальнейшей обработки в АБС.
3. **Интернет-банк**
	1. Реализация потоковой выгрузки заявок на депозит через CDC в топик Kafka DepositRequests.
	2. Реализация потоковой загрузки состояния заявок на депозит через IBLoader из топика IBRequestsSync.
	3. Реализация интеграция И.Б. с SMS-шлюзом для отправки SMS-кода для подтверждения создания заявки на депозит.
4. **АБС**
	1. Разработка раздела для работы с предварительными заявками.
	2. Разработка раздела для расчёта дебетовых ставок на основании данных по открытым депозитам, их ставкам, выданным кредитам, ставки рефинансирования ЦБ.
	3. Разработка процесса обработка заявки на депозит сотрудниками отдела депозитов и сотрудниками отдела кредитов. Разработка функций для оценки кредитного риска в рамках заявки на депозит. Необходимо также учесть, что заявки могут быть особого типа - персональное предложение.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
В качестве альтернативных вариантов рассматривалась прямая синхронизация между базами данных АБС и ИБ. Такой вариант не подошёл в силу требования, что онлайн-системы при прямой работе с АБС будут сильно нагружать Oracle, что приведёт к проблемам в функционировании банковских систем в основное рабочее время.

**Недостатки, ограничения, риски**
* У текущего решения предполагается риск, что загрузка в АБС потока предварительных заявок на депозит с сайта и заявок на депозит из Интернет-Банк будет достаточно медленной в силу высокой загруженности АБС, и заявки могут долго ожидать обработки, так как могут накапливаться в Kafka. Для борьбы с этим риском предполагаются следующие шаги:
	* Организационный: обозначить пользователям регламент по времени обработки заявок, как предварительных, так и прямых.
	* Технический: провести работы по вертикальному масштабированию AБС.
